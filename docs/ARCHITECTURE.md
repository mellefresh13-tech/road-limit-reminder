# Архитектура MVP

## Назначение

Показывать текущий лимит дороги, на которой находится автомобиль. Навигация, маршруты, карты и поиск адресов не входят в продукт.

## Поток данных

1. Android Location API получает координаты, скорость, bearing, точность и время измерения.
2. Location foreground service передаёт GPS fix в сетевой слой.
3. Overpass загружает дорожные сегменты вокруг точки, а также окружающую область страны и OSM-полигоны населённых пунктов.
4. Map matching оценивает расстояние до сегмента, согласованность направления и непрерывность движения.
5. Domain resolver сначала проверяет явные OSM-ограничения; если их нет, для Беларуси применяет базовые правила главы 11 ПДД при наличии контекста страны и населённого пункта.
6. UI и постоянное Android-уведомление получают известный лимит либо причину отсутствия достоверных данных.

## Принципы map matching

Ближайшая геометрия сама по себе недостаточна: на развязках и параллельных дорогах она может выбрать неверный сегмент. Кандидаты должны оцениваться с учётом:

- расстояния от GPS fix до геометрии;
- направления движения относительно направления сегмента;
- предыдущего выбранного сегмента;
- точности GPS и возраста измерения.

При низкой уверенности значение не показывается. Нельзя продолжать показывать старый лимит после потери GPS или смены дороги без явной индикации устаревания.

## Разрешение ограничения

1. Явное числовое ограничение OSM имеет приоритет.
2. Conditional, variable, lane-specific и direction-specific значения не сводятся к одному числу.
3. Для Беларуси используются базовые значения ПДД РБ: 60 км/ч в населённом пункте, 120 км/ч на автомагистралях/дорогах для автомобилей вне населённого пункта, 90 км/ч на остальных дорогах вне населённого пункта, 20 км/ч на living_street.
4. Контекст страны и населённого пункта извлекается из OSM area-объектов. Если страна не определена, национальный fallback не применяется.
5. Отсутствие полигона населённого пункта в OSM не гарантирует, что место юридически находится вне населённого пункта; полнота геоданных требует полевых проверок.

## Слои

- domain: типы ограничений, парсинг OSM-тегов, map matching и правила достоверности.
- data: Overpass API, разбор геометрии дорог и административного контекста.
- location: получение геопозиции в foreground service.
- presentation: экран текущего ограничения и уведомление с динамическим значком.
