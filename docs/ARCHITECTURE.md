# Архитектура MVP

## Назначение

Показывать текущий лимит дороги, на которой находится автомобиль. Навигация, маршруты, карты и поиск адресов не входят в продукт.

## Поток данных

1. Android Location API получает координаты, скорость, bearing, точность и время измерения.
2. Location foreground service передаёт измерение в локальный resolver.
3. Resolver ищет близкие дорожные сегменты в локальном индексе.
4. Map matching оценивает расстояние до сегмента, согласованность направления и непрерывность движения.
5. Data resolver читает атрибуты сегмента и определяет применимость ограничения.
6. UI получает типизированный результат: известный лимит, отсутствие данных или неоднозначный результат.

## Принципы map matching

Ближайшая геометрия сама по себе недостаточна: на развязках и параллельных дорогах она может выбрать неверный сегмент. Кандидаты должны оцениваться с учётом:

- расстояния от GPS fix до геометрии;
- направления движения относительно направления сегмента;
- предыдущего выбранного сегмента и топологической связности;
- точности GPS и возраста измерения;
- скорости автомобиля и правдоподобности перехода.

При низкой уверенности значение не показывается. Нельзя продолжать показывать старый лимит после потери GPS или смены дороги без явной индикации устаревания.

## Слои

- `domain`: типы ограничений, парсинг OSM-тегов, правила достоверности.
- `data`: импорт/хранение дорожных сегментов и поиск кандидатов.
- `location`: получение геопозиции в foreground service.
- `presentation`: экран текущего ограничения и статусы.

Первый этап содержит только основу Android-приложения и доменный парсер. Следующие этапы будут добавляться небольшими PR с тестами.
